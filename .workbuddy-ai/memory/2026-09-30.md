## 第四阶段：接入真实 Notion 同步（commit `6345ede`）

**背景**：用户提供了 Notion Integration Token（存于 `.env`，已被 gitignore 保护，未入库）。首次配置即暴露了构建链的多处缺失，逐一修复。

### 关键发现与修复

**1. 构建脚本不加载 `.env`（阻塞性缺口）**
`build.js` 读 `process.env.NOTION_TOKEN`，但 Node 默认不读 `.env` 文件 → 光建 `.env` 无效。
修复：`build.js` 新增零依赖 `loadDotEnv()`，在 `run()` 最开始调用（`parseArgs` 之前）。
**规则：已存在于 `process.env` 的变量不覆盖**，保证 CI / 部署平台注入优先。

**2. 数据源 ID 全部配错**
`notion-map.json` 的 `dataSourceId` 填的是 `collection://` 格式（Notion REST API **不支持**），`pageId` 填的才是真 database_id（部分正确）。
实测结果：method/travel/words 的 `pageId` 恰好是 database_id（200 OK）；library 的 `pageId` 是页面 ID（400）；ai 是页面无数据库。
修复：用 `POST /v1/search` + `filter={property:"object",value:"database"}` 列出集成可见的全部 28 个数据库，定位到真实 ID：
- library `1a0f5433-9d28-8139-bfce-e3b9ba76ce25`（库名「书库」）
- method `1a3f5433-9d28-8009-9689-d01fdd5c0af3`
- travel `3eaf5433-9d28-8075-823b-e1f56aebe809`
- words `1a3f5433-9d28-8000-917f-de1d1a98f332`
- **ai 无数据库**：AI 学习页下是 4 个 `child_page`（空壳页面，零字段）→ 新增 `type: "page"` 数据源类型

**3. 书库属性名全部对不上（严重）**
实测「书库」真实属性：`阅读状态`(status类型) / `评分`(multi_select，值是 ⭐⭐⭐) / `作者`(relation→作者库) / `封面`(files) / `书名`(title)。
原映射填的是 `状态`/`评分`(number)/`作者`(rich_text) → 字段全读空。
修复：`notion.js` 新增 4 种字段类型：
- `status`：取 `raw.status.name`（Notion 新版 status，区别于 select）
- `stars`：`multi_select` 里的 ⭐ 数量 → 0~5 数字
- `relation`：**需二次查询**关联页面取标题（新增预解析阶段，串行避速率限制），已成功解析 12/12 作者
- `title_const`：按标题查表赋值（用于 AI 页面型数据源无状态字段时手工指定）

**4. ⚠️ Notion 图片是 1 小时过期的签名 URL（隐蔽且严重）**
Notion 上传的文件返回 `prod-files-secure.s3...?X-Amz-Expires=3600` 的临时签名链接 → **构建后 1 小时线上必然破图**。
实测：12 本书中「明朝那些事」「三体」中招。
修复：`normalize.js` 新增 `isExpiringUrl()`，识别 `X-Amz-Expires`/`X-Amz-Signature`/`secure.notion-static.com`/`prod-files-secure.s3.` 并降级为渐变。

**5. 加粗信息丢失（真实缺陷）**
`blocksToBody/Notes/Sections` 用 `richText()` 把多段富文本拼成纯文本，丢掉 Notion 的 `annotations.bold`。
修复：新增 `richTextMarked()` 把 bold 还原为 `**标记`（模板与小程序都支持解析），仅用于正文/笔记类，标题等纯文本字段继续用 `richText`。实测还原出 **186 处加粗片段**。

**6. 模块级降级（用户选择的粒度）**
原行为：任一模块失败就整体回退本地。
修复：`notion.js` 的 `fetchAll` 返回 `failed[]`；`build.js` 新增 `mergeByModule()`，**只把失败模块**用本地数据回填，其余模块继续用 Notion。已注入故障实测：library 假 ID + travel 假页面 → 二者独立回填本地，ai/words 仍用 Notion 值。

**7. 测试断言写死了旧基线（测试代码问题，非产品缺陷）**
`verify.js` 硬编码 `ai=3/words=74`、`sim-miniprogram.js` 硬编码计数与 `book-001`/`article-001`/`trip-001` id、`verify-miniprogram.js` 同样硬编码前缀 id。

## 第五阶段：Cloudflare Pages 部署支持（commit `41a9dbb`）

**需求**：部署到 Cloudflare Pages（选 Git 集成方式）。

### 关键技术结论（重要，避免走弯路）

1. **Cloudflare Pages 的 Git 集成不读 `wrangler.toml`**
   Git 集成的构建参数（Build command / Output directory / 环境变量）全部在**控制台**配置。
   `wrangler.toml` 的 `[build]`/`[[headers]]`/`[[redirects]]` 只适用于 Direct Upload。
   → 我最初创建的 `wrangler.toml` 是**错的**，已删除。

2. **响应头必须用 `_headers` 纯文本文件，放在构建输出目录**
   即 `site/dist/_headers`（不是仓库根目录、不是 wrangler.toml）。
   语法：`[url-pattern]` 一行，随后**空格缩进**的 `Name: value` 行（**不能用 Tab**）。
   已由 `tools/seo.js` 新增 `buildHeaders()` + `build.js` 自动生成。

3. **自定义 404 靠输出目录里的 `404.html`，不需要 `_redirects`**
   Cloudflare 文档明确：`_redirects` 只支持 301/302/303/307/308 跳转（Rewrites ❌）。
   写 `/  /404.html  404` 会被忽略。项目已有 `404.html`，开箱即用。

4. **`NOTION_TOKEN` 必须在 Cloudflare 控制台配置**
   本地 `.env` 被 gitignore，CI 读不到 → 线上会降级为本地数据（构建仍成功，站点可访问，只是不同步 Notion）。

### 改动
- `tools/seo.js`：新增 `buildHeaders()`
- `tools/build.js`：输出 `_headers` 到 `site/dist`，并加入 `copySiteToDist` 防覆盖列表
- `tools/verify.js`：新增 `_headers` 存在性/内容规则/无 Tab 缩进校验 + `404.html` 约定校验
- `docs/deploy-cloudflare-pages.md`：新建，含 Git 集成与 wrangler 两种方式、配置表、验证清单、FAQ
- `README.md`：补充 Cloudflare 部署段落
- 删除无效的 `wrangler.toml`

## 阶段：自动定时构建（同步 Notion 更新）— commit `90e2440`

### 问题
Cloudflare Pages 默认只在 `git push` 时构建。内容源是 Notion，Notion 改了内容仓库不变 → 线上不更新。

### 方案：Deploy Hook + 定时器
- **Deploy Hook**：Pages → Settings → Builds → Add deploy hook，得到唯一 URL，POST 即触发构建，无需认证（等同密码，必须存 secret）。
- 两种定时方案二选一，**不要同时启用**（重复构建浪费额度）。

#### 方案 A：Workers Cron Trigger（推荐，已内置 `cloudflare/rebuild-worker/`）
- `src/index.js`：ES modules，`scheduled(controller, env)` POST `env.DEPLOY_HOOK_URL`；
  - 未配置 secret → 日志提示 + `controller.noRetry()`
  - 4xx → `noRetry()`（配置问题，重试无意义）
  - 5xx → throw（交给 Cloudflare 重试）
  - `fetch()` 额外提供 `POST /rebuild`，由 `REBUILD_TOKEN`（header `x-rebuild-token`）保护；未设置该 secret 时端点自动 403
- `wrangler.toml`：`crons = ["0 1 * * *"]`；**cron 按 UTC 执行**，北京时间 = UTC+8 → 默认北京 09:00
- `package.json` 需 `"type": "module"`（否则 test.js 的 import 报 Cannot use import outside a module）
- `test.js`：7 场景 / 15 断言，全部通过

#### 方案 B：GitHub Actions（已内置 `.github/workflows/rebuild.yml`）
- **定时默认注释关闭**，仅保留 `workflow_dispatch` 手动触发 —— 避免与方案 A 重复构建
- 启用：取消 `schedule` 注释 + 仓库 secret `DEPLOY_HOOK_URL`
- 注意 Actions 的 schedule 也按 UTC，且仓库长期无活动可能被停用、高峰延迟数分钟

### 关键事实（查官方文档确认）
- Pages 构建额度：**Free 500 次/月、并发 1**；Pro 5000/5；Business 20000/20；单构建超时 20 分钟
- cron 改动需重新 deploy，**最多 15 分钟**在全球生效
- 建议每天 1 次（≈30 次/月）；`*/30 * * * *` ≈1440 次/月会超免费额度
- Worker 执行记录：Workers → Settings → Trigger Events → View events（保留最近 100 次）
